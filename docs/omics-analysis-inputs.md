# Omics analytical input workflow

## Purpose

A valid public-omics snapshot establishes which local files were retained and their SHA-256 identities. It does not establish that an exported assay is rectangular, numerically coherent, correctly oriented, or aligned with one-row-per-sample metadata.

The analytical-input workflow adds that next reproducibility boundary:

```text
registered public source
→ validated local snapshot
→ declared assay and metadata export
→ structural analytical-input validation
→ later QC, normalization, modelling, and interpretation
```

The validator remains offline-first. It does not download data, install packages, normalize values, impute missing cells, infer groups, fit models, or treat a structurally valid matrix as biologically valid evidence.

## Analysis directory

A minimal directory contains:

```text
analysis/
├── analysis_plan.json
├── sha256_manifest.json
└── derived/
    ├── assay.csv
    └── samples.csv
```

`sha256_manifest.json` is the valid parent snapshot manifest generated by `cb-omics-inspect`. The assay and metadata are learner-selected exports derived from that snapshot. Their paths must be normalized relative POSIX paths and must not be symbolic links.

## Plan schema

```json
{
  "schema_version": 1,
  "source_id": "bioconductor.airway",
  "parent_snapshot_manifest": "sha256_manifest.json",
  "assay": {
    "path": "derived/assay.csv",
    "delimiter": "comma",
    "feature_id_column": "feature_id",
    "value_scale": "raw_counts",
    "allow_missing_values": false
  },
  "sample_metadata": {
    "path": "derived/samples.csv",
    "delimiter": "comma",
    "sample_id_column": "sample_id"
  },
  "required_metadata_columns": [
    "condition",
    "batch"
  ]
}
```

Supported delimiters:

- `comma`;
- `tab`.

Supported value scales:

- `raw_counts`: observed cells must be finite, non-negative integers;
- `nonnegative_continuous`: observed cells must be finite and non-negative;
- `real_continuous`: observed cells may be negative but must remain finite.

The scale is a declared structural contract. It does not prove that a transformation, normalization method, or inferential model is appropriate.

## Assay orientation

The assay contract is strictly feature-by-sample:

```csv
feature_id,S1,S2,S3
ENSG000001,10,11,12
ENSG000002,0,4,8
ENSG000003,5,5,5
```

The validator checks:

- a non-empty header;
- unique, unpadded column names;
- presence of the declared feature identifier column;
- at least one sample column;
- constant row width;
- non-empty, unique feature identifiers;
- numeric and finite observed cells;
- compatibility with the declared value scale;
- missing-cell counts and the explicit `allow_missing_values` decision;
- SHA-256 identity and deterministic dimensions.

A duplicated feature identifier is an error because the analytical level is ambiguous. The validator does not silently aggregate transcripts, peptides, proteins, protein groups, probes, or genes.

## Sample metadata

Metadata must contain exactly one row per declared sample identifier:

```csv
sample_id,condition,batch
S1,control,A
S2,treated,A
S3,treated,B
```

The validator checks:

- unique columns;
- the declared sample ID column;
- every required metadata column;
- non-empty required cells;
- unique, unpadded sample IDs;
- constant row width;
- exact set equality between assay sample columns and metadata rows.

If the sample sets match but their order differs, the input remains valid with a warning. Downstream construction must join by sample ID rather than assume positional correspondence.

## Missing values

Missing assay values are not automatically treated as invalid because proteomics and other omics workflows may legitimately contain incomplete quantitative matrices. Their presence must be explicit:

```json
"allow_missing_values": true
```

This produces a warning and records the missing fraction. It does not choose an imputation method or missingness mechanism. With `allow_missing_values: false`, every empty assay cell is an error.

Required metadata cells cannot be missing. A row without a declared condition, batch, subject, time point, or other required design variable cannot silently enter modelling.

## Parent snapshot lineage

The parent snapshot manifest must contain:

- `valid: true`;
- the same stable source ID;
- the registered accession;
- a 64-character hexadecimal snapshot fingerprint.

The analysis transition manifest records:

- parent manifest path and SHA-256;
- parent snapshot fingerprint;
- analysis plan SHA-256;
- assay and metadata SHA-256 values;
- dimensions and numerical profiles;
- sample-set and order checks;
- all warnings and errors;
- a root-independent transition fingerprint.

This links an analytical export to a specific validated source snapshot. It does not prove that the export was generated correctly; the transformation script or notebook must still be preserved separately.

## Command

```bash
cb-omics-analysis-inspect bioconductor.airway data/analysis/airway \
  --manifest data/analysis/airway/analysis_manifest.json
```

For the registered proteomics source:

```bash
cb-omics-analysis-inspect proteomexchange.pxd000001 data/analysis/pxd000001 \
  --manifest data/analysis/pxd000001/analysis_manifest.json
```

The command returns exit code `0` when no error-level findings exist and `2` otherwise.

## Scientific boundary

A valid analytical input demonstrates only that:

1. the parent snapshot identity is declared;
2. assay and metadata files are stable local files;
3. the matrix has a coherent feature-by-sample structure;
4. identifiers and numeric cells satisfy the declared contract;
5. assay and metadata samples align by ID.

It does not establish:

- independence of biological replicates;
- correctness of treatment, batch, subject, or time-point labels;
- adequacy of sample size;
- suitability of normalization or transformation;
- a missing-at-random mechanism;
- absence of confounding or leakage;
- validity of differential, multivariate, enrichment, or predictive models;
- generalizability beyond the represented experiment.

The next backend stage should create immutable derived-analysis manifests for QC, filtering, normalization, design matrices, and model outputs while preserving this parent transition fingerprint.
